在远端改代码，
怎样在本机左侧看到 diff？

你的需求是：连接远程机器 → 在那台机器运行编码工具 → 文件仍保存在远端 → 本机左侧 tab 显示红绿变更统计，点击查看文件 diff。v0.9.0 起，原生 SSH tab 可直接查看远端 Git diff；需要完整远程文件树时可创建远程工作区。

左上角工作区名称 → New Workspace… → Host 选择 SSH 主机

先弄清两个入口照着截图操作diff 会怎么显示没有显示时检查
v0.9.0 / 原生 SSH Git

直接使用顶部「＋ → SSH」查看远端 diff

  1. 用应用的原生 SSH 菜单或保存的主机配置连接服务器。
  2. 在远端进入 Git 仓库，确认 shell 集成报告了当前目录。
  3. 在左侧查看远端分支与 +N −M，点击数字打开该面板所属仓库的 diff。

此路径复用现有 SSH 连接，不需要为 Git 安装 tty7-server。支持未跟踪文件预览、完整上下文和外部修改刷新；连接断开时清除旧结果，重连后重新读取。

要求 POSIX 远端 shell，以及支持 --path-format=absolute 的 Git。手动嵌套 SSH 不提供此路由。下面保留的远程工作区步骤适用于需要完整远端文件树的场景，入口截图来自 2026-10-28 的已安装版本。

01 / 两个入口

都是 SSH 连接，工作范围不同

你截图中的「＋ → SSH」

是在当前工作区里增加一个 SSH 终端 tab。终端运行在远端，但当前工作区仍然是本地的 cloudy’s local。v0.9.0 起，应用会通过该面板已有的原生 SSH 连接查询远端 Git 状态和 diff。手动在终端输入的嵌套 ssh 命令不在此范围。

进入远端仓库并让 shell 集成上报目录后，左侧会显示远端分支和增删统计，点击数字即可查看只读 diff。

你要用的「New Workspace → Host」

把整个新工作区托管在远端。文件树、Git 状态、diff 查询都指向那台远程机器，界面仍在本机显示。远端仓库不需要同步回本机。

「Add SSH Host…」为什么两个地方都有？

它们共用同一套 SSH 主机配置。保存一次服务器后，可以从「＋」打开一个 SSH 终端，也可以在「新建工作区」的 Host 中选择它。添加主机不是创建远程工作区；选择主机后从哪个入口继续，才决定用途。

02 / 实际入口

按这条路径操作

以下截图来自你的当前应用。现在不需要重新去点顶部「＋」。

STEP 1

点左上角工作区名称，再点底部 New Workspace…

点击 cloudy’s local 旁的上下箭头，就会出现右图的工作区切换器。

新建按钮在这个弹窗的底部，不是终端 tab 上方的「＋」。

Windows 也可以用 Ctrl + Shift + O 打开工作区切换器。

STEP 2

找到 Host，把 This Computer 改为你的远端主机

Name 是工作区名称，例如你自己起一个项目名。

Host 才决定工作区运行在哪台机器。默认的 This Computer 代表本机；要点击它选择远程服务器。

STEP 3

没有服务器条目时，先添加并保存 SSH 主机

此次截图中，列表只有 This Computer、Ubuntu 和 Add SSH Host…，没有列出已保存的 SSH 主机。

点击下方 Add SSH Host… 添加主机；也可从设置里的 SSH 主机管理保存配置。之后重新走 Step 1 → Step 2，在 Host 中选中那台服务器。

你以前连接成功过，不会自动把当前本地工作区转换成远程工作区。这里按当前实际显示的主机列表选择。

STEP 4

选好 SSH Host 后创建，首次按提示安装远端服务

  1. 确认 Host 已显示你的 SSH 主机名称，而不是 This Computer。
  2. 确认工作区名称并创建。应用会通过该 SSH 连接访问远端。
  3. 首次使用远程工作区时，应用可能提示安装匹配版本的 tty7-server。它负责远端工作区、文件和 Git 查询；单纯开一个 SSH Shell 不需要同样的工作区服务。
  4. 在弹出的安装说明中核对目标主机和安装位置，然后由你确认安装。

这一阶段是操作说明：本次没有连接你的实际服务器、安装服务或创建远端工作区。已实机核实的是前面三个入口和表单。

STEP 5

在远程工作区的终端里进入远端仓库，再启动编码工具

工作区创建后，在它的终端里进入真正要改的项目目录，再启动你要用的编码工具。你提到的工具只要实际修改了该 Git 仓库里的文件，就会产生可供 Git 比较的变化。

# 以下路径仅作示例，替换为远端真实项目路径
cd /path/to/your/repository
git rev-parse --show-toplevel
git status --short

如果你已处于远程工作区，终端本来就运行在那台远端机器上；直接进入项目即可，不需要再在其中套一层 SSH 连接。

03 / 你想看到的结果

本机左侧显示统计，点击打开远端文件 diff

这里的 tab 就是你说的左边「Table」。在远程工作区中，修改远端仓库后，应用会通过远端服务读取 Git 状态，左侧 tab 可显示分支和红绿增删统计；点击红绿数字打开 diff 视图，查看文件与具体增删行。

远端项目 tab · 分支名   +新增行数   −删除行数   ← 点击这组数字

上面是结构示意，不是你的远端实测截图。当前还没有替你建立远程工作区，因此没有把本机截图当成远端 diff 证据。

通常不会自动生成一个 .diff 文件

编码工具通常直接改源文件。Git 比较改前改后的内容，应用把比较结果显示成红绿 diff。除非主动导出补丁，否则不必出现一个单独的 .diff 文件。

统计是 Git 变化，不是某一轮对话的记录

左侧 +N −M 对应仓库相对 HEAD 的增删统计。它可能包括你手改的内容和 Agent 多轮修改；已经提交后的变化，不再属于当前未提交的 diff。

和刚才的 SSH 恢复修复是什么关系？

PR #217 解决的是 SSH 连接与已知 Agent 会话在重启、重连后的恢复。PR #224 随 v0.9.0 为本地工作区中的托管原生 SSH tab 增加了远端 Git 状态与 diff；两项功能共同覆盖重连和重新附着。

再看一次：顶部「＋」里的 SSH 是什么？

这就是你最初截图的菜单。选择已保存的主机后，它会在当前工作区增加一个 SSH 终端。

这个入口现在同时支持远端 Shell 与只读 Git diff；需要整个远端文件树和工作区级 Git 操作时，使用前面的新建工作区路线。

04 / 没出现 diff 时

先确认机器和目录，再看 Git 是否有变化

我 SSH 连通了，左侧还是没有红绿数字

先确认正在运行 v0.9.0 或更新版本，并通过应用菜单创建托管的原生 SSH tab；进入远端 Git 仓库，确认 shell 集成已上报远端目录。旧版本可使用 Host 选了远端主机的新工作区。仅看到 SSH 图标或成功登录，不能证明整个工作区已经由远端托管。

Host 里找不到以前连过的服务器

当前实拍列表没有保存的 SSH 主机条目。先添加并保存主机配置，再重新进入 New Workspace 的 Host 列表。若仍没有，核对当前应用所用的配置与之前连接时是否一致；不要把 Ubuntu WSL 当成你的外部服务器。

已经是远程工作区，还是看不到变更

在该工作区的终端中确认目录属于 Git 仓库，并且改动已经保存到远端磁盘。可执行以下只读 Git 查询：

git rev-parse --show-toplevel
git status --short
git diff --stat HEAD

如果最后一条没有输出，左侧可能没有可显示的相对 HEAD 增删统计。新建但尚未跟踪的文件要同时看 Git 面板的未跟踪文件列表；不要只用数字判断文件是否存在。忽略文件、仓库外文件或已提交内容也不一定表现为当前红绿数字。

工具刚改完，统计还没更新

仓库中的刷新逻辑会在目录变化、命令结束、Agent 一轮结束及部分工具活动时更新 Git 状态。先确认文件已保存，等当前命令或一轮任务结束，再查看 Git 面板；连接断开时也需要先恢复远端服务连接。

我在远程工作区里又 SSH 到了另一台机器

当前工作区的服务对应第一台机器，无法据此保证第二台机器的 Git 查询。要在本机界面查看第二台机器的 diff，应直接为第二台机器创建对应的远程工作区。

核实范围

已实机确认：你当前安装应用的工作区切换器、New Workspace 表单、Host 下拉列表，以及顶部加号 SSH 菜单。页面中的图来自这些真实界面，红框只用于标出入口。

已核对仓库实现：远程工作区的文件/Git/diff 通过对应主机执行；本地工作区中的 SSH pane 不把远端目录交给本机 Git；左侧红绿统计点击后打开 HEAD 范围的 diff。

尚未替你执行：连接真实远端、安装 tty7-server、启动真实编码工具、在远端改文件并验收 diff。后续操作按本文步骤由你在目标服务器确认。
