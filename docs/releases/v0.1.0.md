# ctty7 v0.1.0

ctty7 v0.1.0 以
[v26.8.3-c.9](https://github.com/cloudy-liu/ctty7/releases/tag/v26.8.3-c.9)
为基线。这是 fork 改用 ctty7 名称后的第一次正式发布，也是 0.x 版本线的起点。
比较范围：
[v26.8.3-c.9...v0.1.0](https://github.com/cloudy-liu/ctty7/compare/v26.8.3-c.9...v0.1.0)。

## 本次变化

- 对外产品名、安装器、应用图标和 GUI 分发包统一为 ctty7 v0.1.0。
  内部 crate、命令、二进制名、配置目录、会话数据、协议标识、Windows
  AppId/AUMID 和 macOS bundle identity 保持 tty7 命名，现有脚本和数据无需迁移。
- 更新只跟随 `cloudy-liu/ctty7` 的正式 Release。Nightly workflow、频道选择器、
  feed 和 manifest 处理已经移除。旧配置仍可读取，但不会选中已删除的频道。
- 旧的 26.x 客户端会把 0.1.0 判断为较低版本，因此需要手动安装一次。
  从下一个 ctty7 版本开始恢复正常的递增更新。详见
  [迁移说明](https://github.com/cloudy-liu/ctty7/blob/main/docs/maintenance/migration.md)。
- 更新器现在处理仓库改名带来的有限重定向，按平台严格选择资产并校验 checksum。
  新下载拥有独立进度，旧请求的完成事件不能覆盖较新的重试。
- Windows 新安装使用 ctty7 名称和目录。覆盖安装保留原 AppId 和 AUMID；
  portable 快捷方式只在确认应用身份和可执行文件目标后替换。
- Agent 状态采用 Herdr 的屏幕规则、五种状态、符号和颜色，并与 hook 报告合并。
  Codex、Cursor 和 Antigravity 等没有完整状态 hook 的 Agent 也能在 tab、sidebar、
  switcher 和 tray 中显示状态。
- CMD/Clink 现在按 OSC 顺序保存命令归属。启动 helper、嵌套 prompt mark、
  排队输入和旧版 Clink callback 不会错误地重新启用 inline editor。
- 并行测试不再让 scrollback sweep 删除其他测试的 fixture。Vi prompt 的 gap input
  会等到 shell 报告输入模式后再交给 inline editor 或 shell。
- GitHub 仓库已改名为 `cloudy-liu/ctty7`，保留 fork 关系、issues、PRs 和历史。
  About 描述与主页已经指向新地址，Pages 保持关闭。

## 从既有 fork 继承的能力

这些能力在 v26.8.3-c.9 基线之前已经存在，本次把它们作为 ctty7 产品文档的一部分，
不把它们重复记为 v0.1.0 新功能：

- GPU 渲染的终端、workspace、tab、split、命令面板、搜索和 source control。
- 后台 daemon 持有的持久会话、工作区恢复和 Agent session 恢复。
- WSL、SSH、SFTP、端口转发和远端 `tty7-server`。
- Windows CMD/Cmder 支持、shell integration、历史搜索和 prompt 编辑。
- Herdr 作为宿主应用的 tab 头像，以及嵌套 Agent 时的宿主优先规则。
- Codex、Claude Code 等 Agent 的检测、状态 hook、通知和 CLI 查询。

   Clink prompt helper 的进程树会让首个可编辑 prompt 被拒绝。该 commit 信任
