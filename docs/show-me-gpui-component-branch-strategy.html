直接回答

ctty7 如何引用

三个相关 crate 使用同一个组件库 revision，避免 UI、资源和宏来自不同版本。

gpui-component = { git = "https://github.com/cloudy-liu/gpui-component", rev = "9572b7fab9c0fcf73e34c6118f8a9f10f083f928", version = "0.5.2", features = ["tree-sitter-languages"], } gpui-component-assets = { git = "https://github.com/cloudy-liu/gpui-component", rev = "9572b7fab9c0fcf73e34c6118f8a9f10f083f928", version = "0.5.1", }

是否创建 ctty7 分支

现在已经创建。ctty7 表达的是“给 ctty7 使用的稳定集成线”。

  • main：跟踪 fork 的主线或上游基线。
  • ctty7：ctty7 的稳定集成分支。
  • feature/*、fix/*：短期开发分支，完成后合入 ctty7。
  • sync/upstream-*：临时同步分支，不作为应用依赖。

一次上游更新的流程

组件库和 ctty7 各自保持清晰的职责

1

从上游更新同步分支

把 l0ng-ai/gpui-component:main 合入 sync/upstream-*。

2

解决定制冲突

保留 ctty7 需要的通用 UI 能力；能回馈上游的改动，单独准备 upstream PR。

3

验证组件库和 ctty7

先跑 gpui-component 测试，再跑 ctty7 的 Markdown、编辑器和完整构建测试。

4

合入稳定集成线

把通过验证的同步结果合入 cloudy-liu/gpui-component:ctty7。

5

ctty7 更新精确 revision

只改 ctty7 的 Cargo.toml 和 Cargo.lock，让发布结果可重复。

GPUI 也应遵循同一原则：组件库和 ctty7 使用匹配的 GPUI revision。当前 ctty7 的组件依赖已经是 fork，但 GPUI 的 patch 仍使用 l0ng-ai/zed:tty7 分支，后续应同样收敛到精确 commit。
