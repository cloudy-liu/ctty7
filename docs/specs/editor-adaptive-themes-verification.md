# Source editor appearance verification

Historical record: the light-palette choice is superseded by
[GitHub Light source editor appearance](editor-github-light.md).

Spec: [cloudy-liu/ctty7#84](https://github.com/cloudy-liu/ctty7/issues/84).
PR: [cloudy-liu/ctty7#86](https://github.com/cloudy-liu/ctty7/pull/86).
Verification date: 2026-10-04 on Windows.

## Current behavior

Every resolved dark application appearance uses Atom One Dark, with opaque
source and gutter background `#282C34`. Every resolved light appearance uses
Atom One Light, with background `#FAFAFA`. One Dark Pro remains an application
preset and uses Atom One Dark in source editors. Theme names do not select a
separate code palette, and the application background does not replace the
Atom background. Appearance shows the active palette without a color picker.

The retired `editor_theme` configuration key is ignored on load and omitted on
save. Legacy automatic, fixed, One Dark Pro, unknown and malformed values do
not discard valid application or source typography preferences. Source font,
font size and line height remain independently saved settings.

## Automated checks

The application and asset packages retain the fixed component revision
`a8bc7a71b974cbf190b86622837e46e4508070e7`. No component or lockfile update was
needed for this normalization.

- The configuration compatibility regression failed before the retired field was removed and passed afterward. It checks all previous editor palette values, unknown strings and malformed values, omitted output, and preservation of other valid preferences.
- The `editor_` application test filter passed 17 tests, including the active-palette settings row, typography Enter/blur submission and bounded values, theme previews, cancellation, configuration reload, authored colors, language coverage and editing-state preservation.
- The application-window system-follow regression passed. It checks both cached system appearances and confirms a disabled system-follow preference prevents the system from changing source appearance. This cached-state test runs on Windows/Linux; macOS refreshes native appearance inside its application theme path.
- The existing state-preservation regression includes One Dark Pro, Dracula, Nord and custom themes with misleading light/dark names, non-Atom gradient backgrounds and opacity. Source and gutter colors remain the specified opaque Atom colors; unsaved text, dirty state, cursor, selection, scroll and undo remain intact.
- Both bundled Atom palettes match regenerated bytes from their fingerprinted sources. Each source retains 74 UI colors and 211 ordered token rules.
- The independent TextMate corpus retains 46 samples, 440 selected token expectations and 21 languages. Tests compare 22 authored editor/control colors, compile all 38 private queries and preserve shared language registrations.
- Host boundary validation passed for 98 UI/terminal files.

The final locked workspace regression passed 2,949 tests with 6 existing
ignored tests and no failures. Formatting and whitespace checks passed.
The locked Windows workspace build passed, including `target/debug/tty7-app.exe`.

## Review

Standards and Spec reviews covered the full PR diff against fork/main, including
the original Atom integration and the independent typography work. Neither
found an actionable implementation issue. A settings-path documentation typo
was corrected. The final test-only Spec follow-up also found no actionable issue.

## Verification limits

Full native application visual acceptance was not performed for this revision.
GPUI application-window interaction tests use headless test windows. Historical
component previews in this directory predate the fidelity correction and this
normalization; they do not establish current full-application acceptance.

Native wallpaper/transparency, local/remote file-open workflows, document
fill/restore and selection/search interactions still need manual inspection.
Existing automated layout and editing regressions do not replace those checks.
macOS and Linux native visual acceptance was not performed.

Tree-sitter maps representative authored TextMate roles rather than implementing
all selector semantics. CMake, C#, GraphQL, Protocol Buffers and Swift currently
have no bundled highlight queries and retain readable foreground text. Semantic
tokens, bracket coloring and arbitrary Markdown fence aliases remain outside
the mapped syntax coverage.
