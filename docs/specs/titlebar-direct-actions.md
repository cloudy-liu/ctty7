# Spec: Direct titlebar command and settings actions

## Problem Statement

用户需要通过标题栏右上角的「…」菜单，再选择命令面板或设置。设置没有独立图标，入口难以发现，打开也多一次点击。用户已经对比侧栏入口、中央搜索框和上游方案，选择右上角紧凑双图标的 A 方案，并明确要求删除两条竖向分隔线，不用其他装饰替代。

## Solution

将标题栏现有的两项「…」菜单替换为两个常驻的图标按钮：放大镜直接打开现有命令面板，齿轮直接打开现有完整设置页。右上角从左到右依次为详情面板开关、命令搜索、设置和平台窗口控制，按钮之间只保留自然间距。

入口沿用现有应用的布局和交互机制，在侧栏标签、顶部标签、侧栏收起以及文档和详情面板打开时保持可见、可点击；保留现有快捷键和用户自定义绑定。

## User Stories

1. 作为需要调整配置的用户，我希望在标题栏直接看到设置齿轮，以便立即找到设置入口。
2. 作为需要调整配置的用户，我希望点击齿轮一次就进入完整设置，以便减少操作步骤。
3. 作为需要执行命令的用户，我希望点击放大镜就打开现有命令面板，以便继续搜索和执行全局操作。
4. 作为使用终端工作台的用户，我希望标题栏保持紧凑，以便把可用空间留给工作内容。
5. 作为选择 A 方案的用户，我希望详情、搜索、设置按固定顺序排列，以便形成稳定的操作习惯。
6. 作为偏好简洁界面的用户，我希望三个图标之间没有竖线、分隔条或替代装饰，以便减少视觉干扰。
7. 作为使用侧栏标签的用户，我希望两个入口直接可见，以便无需展开菜单。
8. 作为使用顶部标签的用户，我希望两个入口仍然可用，以便切换布局后继续操作。
9. 作为收起侧栏的用户，我希望两个入口仍在右侧，以便节省空间时不丢失功能。
10. 作为阅读停靠文档的用户，我希望文档标题和工具栏为这些入口预留正确空间，以便按钮不被遮挡。
11. 作为使用填满工作区的文档视图的用户，我希望命令与设置入口仍可点击，以便阅读时仍能调整应用。
12. 作为打开详情面板的用户，我希望入口沿用现有平台窗口角落位置，以便面板打开时仍能找到它们。
13. 作为使用窄窗口的用户，我希望图标的点击区域和窗口控制不互相覆盖，以便准确操作。
14. 作为依赖快捷键的用户，我希望命令面板与设置的现有快捷键继续有效，以便保持已有习惯。
15. 作为修改过快捷键的用户，我希望图标悬停提示显示当前生效的绑定，以便界面信息与真实行为一致。
16. 作为需要识别图标用途的用户，我希望按钮提供本地化名称和悬停说明，以便理解搜索和设置的用途。
17. 作为使用浅色或深色主题的用户，我希望新按钮沿用现有标题栏图标样式，以便外观协调。
18. 作为从命令面板进入设置的用户，我希望原有设置命令继续工作，以便不同入口都指向同一能力。
19. 作为查看快捷键配置的用户，我希望继续在现有设置中访问按键绑定，以便不用学习新位置。
20. 作为继续操作终端的用户，我希望关闭命令面板或设置后保留现有的焦点恢复行为，以便顺畅返回工作。

## Implementation Decisions

- 使用已经确认的 A 方案，不引入中央常驻搜索框或侧栏底部操作区。
- 在应用共用的窗口角落工具栏中替换两项溢出菜单，复用现有命令面板和设置操作；删除不再使用的菜单构建逻辑。
- 详情面板开关、命令搜索和设置复用现有标题栏按钮和图标尺寸、按钮间距、透明静态底色与悬停反馈；用户进一步明确要求与现有设计融合，不另起一套尺寸或间距。使用自然间距，不新增分隔线、按钮组边框或装饰容器。
- 为新按钮提供可访问名称和本地化悬停说明，快捷键提示使用当前生效的绑定，包括用户改绑或清空绑定后的结果。
- 同步窗口角落的宽度预留，让标签栏、文档停靠标题、填满工作区的文档和右侧面板沿用相同的三个按钮尺寸，避免遮挡和重复入口。
- 保持现有平台窗口控制和窗口拖拽区域规则，不把平台窗口按钮作为新的自绘功能实现。
- 设置页结构、命令列表、按键绑定配置、焦点恢复、配置格式和平台快捷键沿用当前 fork。现有能力只调整入口，不作为新增功能。
- 规格和任务发布在 fork 的 GitHub Issues，使用 ready-for-agent 标签、原生子任务关系；由一个集成分支和一个实现 PR 交付。

## Testing Decisions

- 用户已确认唯一代码测试入口为项目已有的 GPUI 应用窗口集成测试：从真实窗口渲染出的按钮位置模拟点击或输入快捷键，观察命令面板和设置是否打开及原有焦点行为是否保持。
- 优先复用现有窗口测试框架、按钮点击测试和文档布局测试先例，不新增独立的测试框架或平行状态模型。
- 测试用户可观察行为：一次点击打开对应界面、不同布局中按钮存在且可点击、按钮与文档工具栏不重叠，以及现有快捷键继续可用。不用源码字符串或内部辅助方法调用次数代替交互验收。
- 采用逐个行为的 red → green 循环；为尚未实现的直接按钮先获得明确失败，再完成最小改动。
- 覆盖侧栏标签、顶部标签、侧栏收起、详情面板开关和文档停靠或填满工作区的代表性组合；验证窗口角落预留宽度与实际按钮范围相容。
- 用原生界面检查统一图标、自然间距、两条竖线均消失及浅色或深色外观。自动化行为测试不代替视觉验收；未现场验证的平台明确记录。
- 执行项目格式检查、与改动相关的应用测试、适当的工作区回归及生产构建；远端 CI 覆盖其他平台。

## Out of Scope

中央常驻搜索框、上游全局搜索体系迁移、设置独立系统窗口迁移、设置页重构、快捷键编辑器重构、快捷设置浮层、侧栏全局操作区、主题或图标系统重做、配置或协议变更，以及本次功能的版本发布。

## Further Notes

用户已经确认 A 方案，并要求：「不要用竖格、分隔线，也不要用任何东西，简洁一点。」HTML 原型已按此更新。本规格实现的是当前 fork 的原生应用，不将原型内的演示设置和上游能力一并加入。

用户已确认一个完整实现 ticket，无阻塞前置任务；窗口角落宽度与不同布局属于同一入口行为的完整性要求，放在同一任务可避免中间状态出现遮挡。
