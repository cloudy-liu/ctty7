# Spec: Add icons to titlebar app menu actions

> Historical decision, superseded by the user's later request to restore
> [direct titlebar actions](../testing/titlebar-direct-actions.md).

## Problem Statement

标题栏「…」菜单中的命令面板和设置只有文字，用户希望更容易区分这两个操作，同时保留熟悉的入口位置和操作习惯。

## Solution

保留原有标题栏与「…」菜单，在「Command Palette…」文字前添加放大镜，在「Settings…」文字前添加设置齿轮。两项继续按原顺序显示，右侧保留现有快捷键。

## User Stories

1. 作为现有用户，我希望继续点击标题栏三个点打开应用菜单，以便沿用已有操作习惯。
2. 作为执行命令的用户，我希望在命令面板文字前看到搜索图标，以便快速识别入口。
3. 作为调整配置的用户，我希望在设置文字前看到齿轮图标，以便快速识别入口。
4. 作为使用应用菜单的用户，我希望菜单项顺序和文字保持一致，以便无需重新学习。
5. 作为依赖快捷键的用户，我希望继续在菜单右侧看到现有快捷键，以便通过键盘执行操作。
6. 作为修改过快捷键的用户，我希望菜单继续使用原有动作与绑定机制，以便保留当前行为。
7. 作为偏好紧凑界面的用户，我希望标题栏保留原有两个按钮，以便不增加常驻控件。
8. 作为使用浅色或深色主题的用户，我希望图标沿用现有菜单的颜色和尺寸，以便外观协调。
9. 作为使用不同界面语言的用户，我希望菜单继续使用现有本地化文字，以便理解操作。
10. 作为使用顶部标签或侧栏标签的用户，我希望这些布局中的同一应用菜单都有图标，以便体验一致。
11. 作为阅读文档或打开详情面板的用户，我希望标题栏和窗口角落保持现有布局，以便控件位置稳定。
12. 作为使用鼠标或键盘的用户，我希望菜单的选择、关闭和动作执行继续遵循现有规则，以便保持熟悉的交互。

## Implementation Decisions

- 在共用应用菜单的两个现有菜单项上使用组件已有的图标菜单项接口。
- 命令面板使用现有搜索图标，设置使用现有齿轮图标。
- 菜单组件统一处理图标栏、文字间距、图标尺寸、颜色、悬停和快捷键对齐；不增加自定义布局或图标资源。
- 保留标题栏的详情面板与三个点、原有角落宽度、菜单锚点、最小宽度、菜单项顺序和动作上下文。
- 保留现有动作分发、本地化、键盘操作和快捷键显示；不修改处理器与快捷键格式化逻辑。
- 不增加分隔线、菜单分组边框或其他装饰。
- 继续通过同一个规格、一个无前置阻塞的实施 ticket 和 fork 上的 PR 交付。

## Testing Decisions

- 复用已经确认的现有 GPUI 窗口测试入口和标题栏、文档布局、窗口拖动、快捷键回归。
- 本次只为两个已有菜单项指定图标，不增加测试框架、源码字符串断言或仅重复图标参数的测试。
- 执行格式检查、相关现有回归与生产构建，远端 CI 验证其他平台。
- 视觉验收应观察真实应用展开后的菜单，确认两个图标位于文字前，快捷键仍在右侧且整体与现有菜单一致。
- 测试记录区分构建、行为回归与原生视觉证据；没有实际检查的界面或平台明确注明。

## Out of Scope

标题栏独立搜索或设置按钮、常驻搜索框、标题栏间距或宽度调整、菜单交互重构、快捷键提示格式化修改、设置页重构、主题或图标系统改造、配置或协议变化，以及发布版本。

## Further Notes

用户最终确认保留三个点和原有菜单，在菜单文字前增加图标，以减少对既有使用习惯的影响。规格、实施 ticket 与 PR 的标题使用英文，正文使用中文。
